# Generic Instanced Mesh Rendering Plan

## Summary

Add a generic ECS/rendering instancing path for grass and repeated props. The
first pass uses one chunk entity containing many authored instances, renderer
CPU frustum filtering, hardware instanced draws, masked alpha materials, and a
reusable transform-plus-params instance payload. Ordinary `MeshComponent`
rendering stays on the current path.

## Key Changes

- Add shared instance types:
  - `rendering::InstanceData { glm::mat4 transform; glm::vec4 params; }`
  - `rendering::InstancedDrawItem` with batch `InstanceId`, mesh id, material
    slot bindings, instance data, revision, layer, visible, and shadow-visible
    flags.
  - `components::InstancedMeshComponent` with `mesh_asset_key`, slot material
    assignments, `std::vector<components::MeshInstance> instances`,
    `uint64_t instance_revision`, `bool dynamic`, `visible`, and
    `shadow_visible`.
- Extend `GraphicsDevice` and backend APIs with
  `submitInstanced(const InstancedDrawItem&)`.
- Retire instanced batches through the existing `retireInstance` path.
- Extend `RenderSystem` with instanced records parallel to current mesh records:
  - Resolve mesh/material slots exactly like `MeshComponent`.
  - Upload instance data when a record is new, `dynamic == true`, count changes,
    or `instance_revision` changes.
  - Keep normal mesh entities and instanced chunk entities independent.

## Renderer Implementation

- Add Diligent instanced batch records keyed by batch `InstanceId`.
- Store submitted `rendering::InstanceData` on the backend record and copy
  visible instances into the existing per-instance vertex buffer path.
- Reuse the existing forward/shadow instancing draw flow after per-instance CPU
  frustum checks.
- Extend the standard vertex input layout from matrix-only to matrix plus
  `float4 InstanceParams : ATTRIB11`.
- Forward standard shaders pass params through for custom/material use.
- Shadow, depth, and camera override shaders accept the same layout and ignore
  params unless needed.
- Keep blended transparent materials correct by falling back to the existing
  sorted transparent draw path per visible instance.
- Defer GPU culling, compact visible buffers, and indirect draws until the
  generic instancing surface has settled.

## Masked Alpha

- Add `MaterialDesc::AlphaMode { Opaque, Masked, Blend }` and
  `float alpha_cutoff = 0.5f`.
- Treat existing `transparent=true` as `Blend` during transition.
- Extend `.mat` files with `render_state.alpha_mode` values `opaque`, `masked`,
  and `blend`.
- Update material resolution and Diligent material records so masked materials:
  - Stay in opaque batching/culling paths.
  - Keep depth writes enabled by default.
  - Use alpha-test pixel shaders for forward rendering.
  - Disable the current depth prepass for masked opaque batches until the
    prepass has equivalent alpha testing.
- Update the grass field material/example to use masked alpha and two-sided card
  geometry, not blended transparency.

## Example

- Add or update a rendering example under `examples/rendering/` showing:
  - A ground plane, skybox/ambient lighting, and free camera.
  - A field of many upright grass cards generated as an
    `InstancedMeshComponent` entity.
  - Per-instance transforms and `params` carrying deterministic position,
    rotation, and scale variation into the vertex input contract.
- Ensure the target name and output path follow the examples directory rules.

## Test Plan

- Material tests:
  - `.mat` loading accepts `alpha_mode=masked`.
  - Invalid alpha modes and cutoffs fail with diagnostics.
  - Material inheritance preserves alpha mode and overrides only specified
    fields.
- Prefab tests:
  - `InstancedMeshComponent` serializes and deserializes instance data and
    material slot bindings.
- Render-system tests with a fake backend:
  - One instanced component submits one instanced draw item, not one draw item
    per instance.
  - Revision, count, and dynamic changes trigger instance updates.
  - Missing slot materials fall back to mesh default materials.
  - Hidden and shadow-hidden flags propagate correctly.
- Backend/build smoke:
  - Build the new grass/instancing example.
  - Run it long enough to verify no Diligent validation crash.
  - Confirm the instanced path renders through shared mesh/material batches.

## Assumptions

- GPU culling and indirect draws are out of the first implementation pass.
- Instance data is intentionally `mat4 + vec4` for now.
- No compact packing, GPU LOD, impostors, or material-driven wind system are in
  this pass.
- Grass placement is generated by the example/runtime code, not a new authored
  foliage asset format.
